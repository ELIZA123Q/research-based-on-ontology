# 人类可读解析 Skill

## 定位

本 Skill 负责解释投研本体生产 Agent 的最终候选交付结果。将模块化 ontology bundle + 生产说明转换为研究员可流畅阅读的解析报告。

**权威规则**：`ontology_bundle_vN/` 是本体内容的唯一权威来源；`_compat/optimized_ontology_vN.json` 只作为兼容回退。过程文件只作为生产过程、证据来源、版本变化和未解决问题的解释上下文。报告只解释原本体，不新增任何内容。

## 规范引用

本 Skill 的完整操作要求、输入识别规则、9 章报告结构、术语翻译、图表生成、写作要求和校验清单，全部定义在：

| 规范文件 | 内容 |
|---------|------|
| `./references/投研本体人类可读解析输出要求.md` | 核心原则（只翻译不重建、研究员语言优先、先全局后细节）、4 种输入形态识别、9 章报告结构（阅读说明→一页概览→能描述什么→通常观察什么→具体覆盖什么→研究逻辑如何展开→哪些可信哪些需验证→阅读提示→技术追溯附录）、术语翻译与字段映射、图表生成规则、写作要求、一致性校验清单、质量门槛 |

## 输入

| 文件 | 说明 |
|------|------|
| `ontology_bundle_vN/` | 候选本体（权威主体） |
| `_compat/optimized_ontology_vN.json` | 兼容回退输入 |
| `docs/production_notes.md` | 优化目标、材料、证据、变化、限制和未解决问题 |
| `_artifacts/sources/source_material_summary.md` | 来源材料摘要（6-5b 输出，可选） |

输入形态：当前场景对应"形态 D（final_results）"——接收生产 Agent 完整输出。

## 输出

- `docs/ontology_guide.md`（9 章结构，完整定义见 `./references/投研本体人类可读解析输出要求.md`）：

```
1. 阅读说明           — 报告边界、本体版本、权威数据选择、推荐阅读顺序
2. 一页概览           — 研究主题、概念范围、对象规模、当前状态
3. 这份本体能描述什么   — 概念层、对象类型、关系类型、当前使用情况
4. 这个行业通常观察什么  — 模板层（行业目录、状态变量、传导模板、传导关系图）
5. 当前本体具体覆盖了什么 — 实例层（行业、公司、产品、材料、资产、观测、事件、假设、信号、判断）
6. 当前研究逻辑如何展开  — 推理链（事件→假设→信号→判断→资产影响）
7. 哪些内容可信/需验证   — 证据与治理层（状态分布、证据等级、缺失证据、未解析项、一致性差异）
8. 研究员阅读提示       — 候选内容、单一来源、需人工审核项
9. 技术追溯附录         — ID 索引、JSON 路径、术语表、一致性检查
```

## 工作流程

1. 识别输入形态（A/B/C/D），定位 `ontology_bundle_vN/` 中的权威概念、对象、关系、动作、推理、证据和治理模块。
2. 读取过程文件作为解释上下文，但不得将其内容当作本体内容写入报告。
3. 按研究员阅读顺序（先概念边界、再全局、再细节）组织 9 章报告。
4. 将技术字段翻译为自然语言，同时保留对象 ID、关系 ID、来源 ID 和 JSON 路径供追溯。
5. 暴露原本体中的缺失项、未连接项、不一致项和标注为 `provisional` 的待审核项。
6. 输出 `docs/ontology_guide.md`。

## 关键规则

### 权威来源规则

| 内容类型 | 唯一来源 | 禁止来源 |
|---------|---------|---------|
| 本体内容（概念、对象、关系、动作、推理、证据、治理） | `ontology_bundle_vN/` | 任何其他文件 |
| 兼容旧输入 | `_compat/optimized_ontology_vN.json` | 只在 bundle 缺失时使用 |
| 优化过程、变更、未解决问题 | `docs/production_notes.md` | 自行推断 |
| 证据来源、可靠性 | `_artifacts/sources/source_material_summary.md` | 自行评估 |

### 不可新增内容

- 不得新增原本体不存在的对象、关系、变量、传导步骤、事实、假设、判断或结论
- 不得使用外部行业知识补全原本体
- 不得把前置材料包（如 reference_materials/）中的逻辑当作已入库本体内容写入报告

### 缺陷暴露

- 原本体中的空字段、缺失关系、未连接的传导链、标注为 `provisional` 的项 → 必须在报告中醒目暴露
- 不得为了报告"好看"而隐藏本体的不完整性
- critical 级缺陷措辞用"严重警告"，minor 级用"已知限制"

### 统计声明

- 所有数值统计（对象数、关系数等）标注"机械统计，自动生成"
- 不自动生成"质量评分"——质量判断属于评测 Skill 的职责

## 禁止事项

除核心规范定义的公共禁止事项外，本 Skill 额外禁止：

- 不新增原本体不存在的对象、关系、变量、传导步骤、事实、假设、判断或结论
- 不使用外部行业知识补全原本体
- 不把前置材料包中的逻辑当作已入库本体内容
- 不修改 `ontology_bundle_vN/` 或 `_compat/optimized_ontology_vN.json`
- 不判断是否发布
- 不自动生成"质量评分"

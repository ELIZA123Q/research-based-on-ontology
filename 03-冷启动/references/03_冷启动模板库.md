# 03-冷启动模板库

本文件为冷启动 Skill 提供七类候选模板。模板只给出最小骨架、常见状态变量、常见关系、验证信号和材料缺口，不确认事实。执行时必须结合用户主题、范围约束和核心 schema 生成具体 `base_ontology`。

## 1. 模板选择原则

| 输入特征 | 首选模板 | 注意事项 |
|---|---|---|
| 行业、赛道、板块、产业主题 | `industry` | 先建行业、环节、产品、公司和状态变量，不直接给资产结论。 |
| 上中下游、供需链、价格链、产能链 | `supply_chain` | 必须显式生成环节连接和变量传导。 |
| 产品、技术路线、材料体系、替代路径 | `product_track` | 重点表达产品依赖、替代、代际、材料约束和良率/成本变量。 |
| 单家公司或公司对比 | `company_research` | 公司对象必须连接产业、产品、资产和关键变量。 |
| 政策、监管、补贴、产业规划 | `policy_theme` | 政策是事件或主题触发，必须落到变量、环节和受影响对象。 |
| 利率、汇率、通胀、流动性、商品价格 | `macro_theme` | 宏观变量要通过传导链落到行业、公司或资产暴露。 |
| 突发事件、订单、制裁、事故、并购 | `event_theme` | 事件必须有时间、主体、受影响变量和验证窗口。 |

当两个模板都合理时，选择一个主模板，最多补充两个辅模板。互斥模板不得混合生成同一对象的不同身份；冲突写入 `template_pressure_test`。

## 2. 通用 MVO 骨架

每类模板至少输出：

- `ontology_metadata`：ID、版本、来源、范围、质量初值。
- `base_ontology_bundle/01_concepts.yaml`：概念体系、关键术语、同义词、纳入/排除/相邻/交叉边界、概念到业务对象的映射。
- 核心研究对象：行业、环节、公司、产品、材料、资产或主题对象。
- 业务结构关系：图谱可生成所需的显式关系。
- 状态变量：可持续观察、可形成假设、可进入传导的变量。
- 传导模板：变量方向、时滞、边界条件和待验证材料。
- 信号：validation、tracking、catalyst、weakening、blocking 中至少覆盖与主题相关的角色。
- 情景路径：base/upside/downside 或成立/不成立/延后兑现。
- 材料缺口：影响骨架可靠性的 P0/P1/P2 缺口。

## 3. 行业模板 `industry`

适用：用户关注一个行业或大赛道。

最小对象：

| 类型 | 生成规则 |
|---|---|
| `Industry` | 主题行业。 |
| `Segment` | 3-6 个关键环节，按研究问题而非百科全链条选择。 |
| `Company` | 只放用户指定或代表性候选公司，默认 candidate。 |
| `Product` / `Material` | 只放影响核心传导的产品和材料。 |
| `StateVariable` | 需求、供给、价格、库存、产能、成本、份额、政策强度、技术进展。 |

关键关系：`segmentBelongsToIndustry`、`segmentConnectsToSegment`、`companyParticipatesInSegment`、`productBelongsToSegment`、`materialUsedInProduct`、`observedOn`。

默认缺口：行业边界、环节连接证据、代表公司清单、核心变量口径、最新供需和价格数据。

## 4. 产业链模板 `supply_chain`

适用：用户关注上下游传导、价格传导、成本传导、产能周期或库存周期。

建模重点：

- 至少生成 3 个链条环节和显式 `segmentConnectsToSegment`。
- 每条主链路必须对应 1-3 个 `StateVariablePropagation`。
- 传导模板必须说明方向、时滞、边界条件和可能阻断因素。
- 不知道具体上下游关系时，不补边，写入材料缺口。

常见变量：上游价格、供给弹性、库存天数、下游需求、订单能见度、产能利用率、利润率、议价权、替代品价格。

默认缺口：价格口径、库存口径、供需时滞、上下游合同结构、替代材料或替代技术。

## 5. 产品赛道模板 `product_track`

适用：用户关注产品、技术路线、材料体系、设备环节、替代路径或渗透率。

建模重点：

- `Product` 是主对象，连接公司、环节、材料和替代/互补产品。
- 使用 `productRelatesToProduct` 表达替代、互补、依赖、代际、集成或使能。
- 使用 `materialUsedInProduct` 表达关键材料用途和约束。
- 技术路线只在可观察变量上落地，例如良率、成本、性能、渗透率、客户验证、量产节奏。

常见变量：渗透率、单价、成本、性能指标、良率、客户认证、量产进度、替代比例、供应约束。

默认缺口：产品定义、技术路线边界、材料清单、客户认证证据、量产或出货数据。

## 6. 公司研究模板 `company_research`

适用：用户关注单家公司、公司对比或业务线。

建模重点：

- 公司必须连接行业、环节、产品和资产。
- 公司间关系用 `companyRelatesToCompany` 表达供应、客户、合作、竞争、代工、授权或投资控制。
- 资产暴露用 `assetExposedToTarget`，不能从公司新闻直接跳到投资结论。
- 公司变量要能回到业务或财务口径。

常见变量：收入结构、订单、产能、毛利率、费用率、客户集中度、产品竞争力、现金流、资本开支、资产定价状态。

默认缺口：业务拆分口径、客户/供应商证据、产品收入占比、订单兑现、财务确认时滞、市场预期。

## 7. 政策主题模板 `policy_theme`

适用：用户关注政策、监管、补贴、产业规划、出口管制或政府采购。

建模重点：

- 政策落为 `Event` 或主题对象，再通过 `eventAffectsVariable` 连接变量。
- 必须区分政策发布、细则落地、执行强度、资金拨付、企业响应和财务兑现。
- 政策受益不能直接写成资产结论，必须经过变量和验证信号。

常见变量：政策强度、补贴金额、执行进度、合规成本、需求拉动、供给限制、国产替代节奏。

默认缺口：政策原文、执行主体、适用范围、时间节点、企业受益路径、历史相似案例。

## 8. 宏观主题模板 `macro_theme`

适用：用户关注利率、汇率、通胀、流动性、商品价格、信用或风险偏好。

建模重点：

- 宏观变量必须通过传导链落到行业、公司、产品、成本、需求或资产暴露。
- 不把宏观方向性判断写成事实观测。
- 必须记录传导时滞和可能失效的边界条件。

常见变量：资金成本、汇率、通胀、信用扩张、需求弹性、风险偏好、原材料价格、库存周期。

默认缺口：指标口径、数据频率、历史滞后关系、行业敏感度、对冲因素。

## 9. 事件主题模板 `event_theme`

适用：用户关注订单、并购、事故、制裁、诉讼、技术突破、价格异动或突发新闻。

建模重点：

- 事件必须有主体、时间、来源和影响范围。
- 使用 `eventRelatesToEvent` 表达事件阶段或因果顺序。
- 使用 `eventAffectsVariable` 或 `eventProducesObservation` 连接变量或观测。
- 必须给出验证窗口、反证条件和后续跟踪信号。

常见变量：订单兑现、供应中断、价格变化、产能影响、监管风险、客户替代、市场预期。

默认缺口：原始公告或新闻源、事件发生时间、影响主体、量化范围、后续验证节点。

## 10. 质量检查

冷启动输出必须通过以下检查：

| 检查项 | 通过标准 |
|---|---|
| 范围清楚 | `scope_type`、默认假设和排除边界明确。 |
| 概念清楚 | `01_concepts.yaml` 说明核心概念、相邻概念、交叉概念和来源缺口。 |
| 骨架可用 | 至少有主对象、关键变量、显式关系、传导模板和材料缺口。 |
| 图谱可生成 | 业务结构关系不是靠文本暗示。 |
| 假设显性 | 候选假设、验证信号和反证条件分层清楚。 |
| 证据诚实 | 未验证内容保持 candidate，并写明待补材料。 |
| 合规边界 | 不含买卖建议、目标价、收益率预测或仓位建议。 |

未通过项写入 `mvo_quality_gate` 和 `cold_start_quality_notes`，不得用自然语言报告掩盖结构缺陷。

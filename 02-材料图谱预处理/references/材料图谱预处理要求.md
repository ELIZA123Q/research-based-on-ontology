# 材料图谱预处理要求

本文件定义如何将非结构化或半结构化投研材料，按 Document→Chunk→Entity→Relationship 分层拆解，受 schema 约束抽取候选图谱结构，并为每个候选元素挂接原文证据片段。

> 适用 Skill：6-1b 材料图谱预处理
> 约束级别：强制

## 1. 分层抽取模型

### 1.1 四层结构

```
Layer 0: Document   — 一份完整的投研材料（一篇研报、一份公告、一条新闻等）
Layer 1: Chunk      — 材料中逻辑自洽的连续段落或章节
Layer 2: Entity     — Chunk 中识别出的候选对象、状态变量、事件、信号
Layer 3: Relationship — Entity 之间的候选关系
```

每层向下拆分时，必须保留到上一层的回溯指针。任何 Entity 或 Relationship 必须能回溯到至少一个 Chunk，进而回溯到 Document。

### 1.2 Document 层

每份输入材料对应一条 Document 记录：

```yaml
- documentId: "DOC-{source_id}"
  sourceId: "SRC-001"              # 对应 source_registry.json
  title: ""
  sourceType: ""                   # policies / announcements / financial_reports / industry_data / reports / news / data_extracts
  publisher: ""
  publishTime: ""
  businessTime: ""
  reliability: high                # 继承自 source_registry
  totalChunks: 0
  processingStatus: processed      # processed / partial / skipped
  skipReason: ""                   # 若 skipped，说明原因
```

### 1.3 Chunk 层

拆分规则：

1. 按逻辑边界拆分：章节、小节、独立段落组、表格、关键数据块。
2. 每个 chunk 应包含一个相对独立的主题或一组紧密相关的事实。
3. Chunk 大小不做硬限制，但一个 chunk 内不应混合多个无关主题。
4. 表格和列表应作为独立 chunk 保留，标注数据结构提示。

```yaml
- chunkId: "CHK-{source_id}-{seq}"
  documentId: "DOC-{source_id}"
  sequence: 1
  sectionPath: ""                  # 章节路径，如 "第三章 > 3.2 成本分析"
  chunkType: prose                 # prose / table / list / mixed
  summary: ""                      # 一句话摘要，用于检索
  textHash: ""                     # 原文片段哈希，用于去重和变更检测
  originalText: ""                 # 原文片段（保留足够上下文）
  estimatedTokenCount: 0
  containsRestricted: false        # 是否包含目标价、评级、推荐语等受限内容
```

### 1.4 Entity 层

从 Chunk 中识别候选对象、状态变量、事件和信号。每类 Entity 有不同的字段要求。

### 1.5 Relationship 层

连接两个 Entity，表达它们之间的候选关系。

## 2. Schema 约束策略

### 2.1 约束优先级

```
1. 用户提供的 ontology_schema（最高优先级）
2. 核心规范 schemas/（objects.yaml, relations.yaml, actions.yaml）
3. Skill 内置的默认类型枚举（最低优先级，标注为"待复核候选项"）
```

### 2.2 对象类型约束

若提供了 schema，优先从 schema 中提取允许的对象类型列表。抽取时：
- 每个候选对象必须归类到某个 schema 定义的类型，或明确标注为"schema 外候选"
- schema 外候选对象必须在 `extraction_quality_report.md` 中单独列出

若未提供 schema，使用以下默认候选类型：

| 类型 | 说明 | 示例 |
|------|------|------|
| `Industry` | 行业/产业 | 半导体、新能源汽车、光伏 |
| `Segment` | 细分环节 | 芯片设计、晶圆制造、封装测试 |
| `Company` | 公司/企业 | 台积电、宁德时代、龙蟠科技 |
| `Product` | 产品/服务 | 磷酸铁锂正极材料、HBM3E |
| `Technology` | 技术/工艺路线 | 3nm 制程、Chiplet、固态电池 |
| `Material` | 原材料/中间品 | 碳酸锂、硅片、光刻胶 |
| `Equipment` | 设备/产线 | 光刻机、刻蚀设备、烧结炉 |
| `Customer` | 客户/下游 | 整车厂、储能集成商 |
| `Supplier` | 供应商/上游 | 锂矿企业、设备厂商 |
| `Policy` | 政策/法规 | 出口管制、补贴政策、关税 |
| `Event` | 事件 | 产能投放、技术突破、并购 |
| `Asset` | 资产 | 矿产资源、专利、产能 |

### 2.3 关系类型约束

优先使用 `schemas/relations.yaml` 中定义的 `relation_groups`：

| 关系组 | 包含关系类型 | 示例 |
|--------|-------------|------|
| `business_structure_relations` | 上下游、供需、竞争、替代、依赖 | A 是 B 的上游供应商 |
| `observable_dimension_relations` | 变量挂载、观测关系 | 毛利率挂载到公司 |
| `research_reasoning_relations` | 影响、验证、阻断、传导 | 锂价下跌影响毛利率 |
| `source_and_record_relations` | 来源追溯、证据链 | 该对象提取自文档 X |

不允许只用自然语言暗示关系；凡参与后续推理的连接必须形成关系实例。

### 2.4 状态变量类型约束

状态变量是挂载到对象上的可观测、可量化的维度：

| 类别 | 示例变量 |
|------|---------|
| 价格类 | 现货价、合约价、加工费、价差 |
| 量类 | 产量、销量、出货量、订单量、产能、产能利用率 |
| 库存类 | 原材料库存、产成品库存、库存周转天数 |
| 成本类 | 原材料成本、制造成本、折旧、运费 |
| 盈利类 | 毛利率、净利率、ROE、单吨利润 |
| 份额类 | 市占率、渗透率、国产化率 |
| 供需类 | 需求增速、供给增速、供需缺口 |
| 政策类 | 补贴强度、关税税率、管制等级 |
| 预期类 | 市场一致预期、分析师预测方向、估值分位 |
| 资金类 | 融资余额、大基金持仓、股东减持比例 |

每个候选状态变量必须挂接到至少一个候选对象，并标注变量类型。

## 3. 候选对象抽取规范

### 3.1 候选对象最小字段

```yaml
- objectId: "OBJ-CAND-{YYYYMMDD}-{serial}"
  name: ""                          # 规范名称
  aliases: []                       # 材料中出现的同义词/别名
  objectType: ""                    # 从 schema 或默认枚举中选择
  governanceLayer: application_workspace
  recordStatus: candidate
  description: ""                   # 从原文提取的描述，不做推断补充
  properties: {}                    # 结构化属性字段
  sourceEvidence:                   # 证据挂载（必填）
    documentId: ""
    chunkId: ""
    originalText: ""                # 原文中提及该对象的片段
    textOffset: ""                  # 在 chunk 中的位置提示
    confidence: 0.0                 # AI 抽取置信度 [0, 1]
    evidenceStrength: medium        # high / medium / low / ambiguous
  extractionNote: ""                # 抽取备注（歧义、边界说明）
```

### 3.2 抽取规则

1. 同一实体在材料中多次出现时，应尽量归并到同一候选对象，在 `aliases` 中保留所有出现的名称。
2. 无法确定是否指向同一实体时，分开登记并在 `pending_review_items.md` 中标注。
3. 材料中明确给出的属性才填入 `properties`，不得用外部知识补全。
4. `evidenceStrength` 判定标准：
   - `high`：原文明确陈述，来源权威（公告、财报、政策原文）
   - `medium`：原文明确陈述，来源为研报、新闻
   - `low`：原文暗示或间接提及
   - `ambiguous`：原文表述含糊，有多种理解可能

## 4. 候选关系抽取规范

### 4.1 候选关系最小字段

```yaml
- relationId: "REL-CAND-{YYYYMMDD}-{serial}"
  relationType: ""                  # 从 relations.yaml 或默认枚举中选择
  sourceObjectId: ""                # 关系的源对象（必须是候选对象 ID）
  targetObjectId: ""                # 关系的目标对象（必须是候选对象 ID）
  direction: directed               # directed / undirected
  recordStatus: candidate
  properties: {}                    # 关系属性
  sourceEvidence:
    documentId: ""
    chunkId: ""
    originalText: ""                # 原文中表达该关系的片段
    confidence: 0.0
    evidenceStrength: medium
    directionCertainty: certain     # certain / uncertain / disputed
  extractionNote: ""
```

### 4.2 抽取规则

1. `sourceObjectId` 和 `targetObjectId` 必须先解析到已有的候选对象；无法解析时放入 `pending_review_items.md`。
2. 关系方向不确定时，`directionCertainty` 标记为 `uncertain`，在 `extractionNote` 中说明可能的替代方向。
3. 原文同时支持多种关系解释时，分别登记，在 `extractionNote` 中交叉引用。
4. 不允许凭空创建两个对象后连接它们；对象和关系都必须有原文依据。

## 5. 候选状态变量抽取规范

### 5.1 候选状态变量最小字段

```yaml
- variableId: "SV-CAND-{YYYYMMDD}-{serial}"
  variableName: ""                  # 规范变量名
  variableCategory: ""              # 价格类 / 量类 / 库存类 / 成本类 / 盈利类 / 份额类 / 供需类 / 政策类 / 预期类 / 资金类
  attachedToObjectId: ""            # 挂载到的候选对象 ID（必填）
  unit: ""                          # 单位
  currentValue: null                # 材料中的当前值（若有）
  valueTime: ""                     # 值对应的业务时间
  trend: ""                         # 材料中描述的趋势方向 rising / falling / stable / volatile / unknown
  sourceEvidence:
    documentId: ""
    chunkId: ""
    originalText: ""
    confidence: 0.0
    evidenceStrength: medium
  extractionNote: ""
```

### 5.2 抽取规则

1. 状态变量必须挂接到候选对象，不允许存在"无主"变量。
2. 若材料只给出定性描述（"大幅上涨"），不强制转换为定量值；在 `trend` 中记录方向，在 `extractionNote` 中说明缺少定量数据。
3. 同一变量的多个观测（不同时间点、不同来源）分别登记，保留冲突。

## 6. 候选事件与信号抽取规范

### 6.1 候选事件最小字段

```yaml
- eventId: "EVT-CAND-{YYYYMMDD}-{serial}"
  eventName: ""
  eventType: ""                     # policy_change / capacity_event / technology_breakthrough / m_and_a / earnings_event / supply_disruption / demand_shock / market_event / other
  eventTime: ""                     # 事件发生时间
  affectedObjectIds: []             # 受影响的候选对象
  description: ""
  sourceEvidence:
    documentId: ""
    chunkId: ""
    originalText: ""
    confidence: 0.0
    evidenceStrength: medium
  extractionNote: ""
```

### 6.2 候选信号最小字段

```yaml
- signalId: "SIG-CAND-{YYYYMMDD}-{serial}"
  signalName: ""
  signalType: ""                    # leading_indicator / confirming_signal / weakening_signal / falsification_condition / catalyst / uncertainty_flag
  attachedToObjectId: ""            # 或 attachedToRelationId
  description: ""
  sourceEvidence:
    documentId: ""
    chunkId: ""
    originalText: ""
    confidence: 0.0
    evidenceStrength: medium
  extractionNote: ""
```

### 6.3 事实与观点的区分

必须区分：

| 标签 | 含义 | 示例 |
|------|------|------|
| `fact` | 可核验的客观陈述 | "2025年公司磷酸铁锂正极材料毛利率为8.1%" |
| `author_claim` | 材料作者的主张或判断 | "我们认为 AI 需求外溢将推动成熟制程 ASP 上行" |
| `forecast` | 对未来的预测 | "预计 2026 年碳酸锂价格将回升至 12 万元/吨" |
| `author_judgment` | 带有主观色彩的评估 | "该公司的成本控制能力行业领先" |
| `restricted` | 受限内容 | 目标价、评级、推荐语、仓位建议 |

`author_claim`、`forecast`、`author_judgment` 不得登记为事实观测（`fact`），必须在 `extractionNote` 中标注内容类型。

## 7. 证据片段索引

### 7.1 证据片段结构

```yaml
- evidenceId: "EVID-{YYYYMMDD}-{serial}"
  sourceDocumentId: ""
  sourceChunkId: ""
  originalText: ""                  # 完整的原文片段引用
  textLocation: ""                  # 在原文中的位置（章节、段落、PDF 页码）
  supports: []                      # 该证据支撑的候选元素 ID 列表
  evidenceStrength: medium
  contentCategory: fact             # fact / author_claim / forecast / author_judgment / restricted
  limitations: []                   # 证据限制（时效、口径、样本偏差等）
```

### 7.2 证据索引约束

1. 每条候选 Entity / Relationship / StateVariable / Event / Signal 必须至少关联一个证据片段。
2. 同一证据片段可以支撑多个候选元素。
3. `originalText` 必须是原文的准确引用（可适当截取上下文），不得改写。
4. 当原文较长时，引用关键句子并标注在 chunk 中的位置。

## 8. 抽取质量报告

### 8.1 报告结构

`extraction_quality_report.md` 必须包含：

```
# 材料图谱预处理质量报告

## 1. 材料覆盖
- 处理材料数量、类型分布
- 未处理材料及原因

## 2. 抽取统计
- 候选对象数量（按类型分布）
- 候选关系数量（按类型分布）
- 候选状态变量数量（按类别分布）
- 候选事件数量
- 候选信号数量
- 证据片段数量

## 3. Schema 匹配
- 命中 schema 定义的类型的比例
- schema 外候选元素清单
- 待补充 schema 的类型建议

## 4. 置信度分布
- high / medium / low 置信度候选比例
- 低置信度候选清单和原因

## 5. 证据强度分布
- high / medium / low / ambiguous 证据强度比例

## 6. 未解析项
- 无法挂接到候选对象的关系
- 无法归并的重复候选
- 缺少挂载对象的状态变量

## 7. 受限内容
- 受限内容数量和隔离方式
- 被标记为 restricted / forecast / author_judgment 的元素清单

## 8. 下游交接
- 可用于 6-8 Evidence Episode 归一的结构化候选
- 需要人工复核后才能进入下游的内容
- 材料缺口提示
```

## 9. 待人工复核清单

`pending_review_items.md` 按以下类别组织：

```markdown
# 待人工复核清单

## 1. 证据不足
- 候选元素 [ID]：[问题描述]，原文仅 [简述]，建议 [复核建议]

## 2. 来源不清
- 候选元素 [ID]：[问题描述]

## 3. 表述含糊
- 候选元素 [ID]：原文 [引用] 存在 [多种理解]，当前暂按 [理解] 处理

## 4. 关系方向不确定
- 关系 [ID]：[A] 和 [B] 之间的关系方向不明确，可能为 [方向1] 或 [方向2]

## 5. 多解释可能
- 候选元素 [ID]：[原文引用] 可能解释为 [解释1] 或 [解释2]

## 6. 冲突待裁决
- [候选A] 与 [候选B] 存在冲突：[冲突描述]，来源分别为 [来源A] 和 [来源B]
```

## 11. 质量门槛

| # | 检查项 | 阻断条件 |
|---|--------|---------|
| 1 | 每个候选对象有原文依据 | 存在 `sourceEvidence.originalText` 为空或为 AI 自行生成的候选对象 |
| 2 | 每个候选关系两端对象可解析 | 存在 `sourceObjectId` 或 `targetObjectId` 指向不存在的候选对象 |
| 3 | 事实与观点已区分 | `forecast` / `author_judgment` / `restricted` 被标记为 `fact` |
| 4 | 受限内容已隔离 | 目标价、评级、推荐语、仓位建议未标记 `restricted` |
| 5 | 证据可回溯 | 关键候选元素无法定位到 chunk 或原文位置 |
| 6 | 冲突未合并 | 对同一事实的不同描述被合并为单一结论 |
| 7 | schema 外元素已标注 | 不符合 schema 定义的候选元素未在质量报告中列出 |

## 12. 边界情况

| 场景 | 处理 |
|------|------|
| 材料为表格/数据为主 | 以结构化字段抽取为主，减少自由文本实体抽取 |
| 材料包含大量图片 | 标注"图片内容未抽取"，在质量报告中记录 |
| 同一实体在材料中名称不一致 | 建立 aliases，标注"待人工确认是否为同一实体" |
| 材料内容超出研究主题范围 | 正常抽取，在质量报告中标注"可能超出主题边界" |
| 多份材料对同一事实有矛盾描述 | 保留各自的候选元素，在 pending_review_items 中标注冲突 |
| 无法确定对象之间的精确关系类型 | 使用最接近的关系类型并标注 uncertain，不要自创关系类型 |
| 材料语言为非中文 | 保留原文引用，翻译为中文摘要放入 extractionNote |
| 无 schema 输入 | 使用默认候选类型，所有候选元素标注"待复核候选项" |

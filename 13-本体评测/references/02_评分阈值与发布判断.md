# 评分阈值与发布判断

## 1. 八个评分维度

每道题按 8 个维度评分，每维 0-5 分。

| 维度 | 评测重点 |
| --- | --- |
| `coverage` | 核心对象、状态变量、关系、事件类型和资产影响是否覆盖 |
| `reasoning_chain_completeness` | 是否形成事件、状态变量、产业链、公司、资产和验证信号链条 |
| `explanation_clarity` | 是否解释因果方向、传导机制、节奏、直接和间接影响 |
| `verifiability` | 是否有验证信号、观察指标、窗口、证实和证伪方式 |
| `boundary_conditions` | 是否说明成立、弱化、失效和适用边界 |
| `falsification_ability` | 是否识别反向变量、链条断点、风险传导和预期差反转 |
| `conclusion_usability` | 是否能支持明确、可跟踪、有不确定性说明的投研判断 |
| `ontology_consistency` | 回答是否由本体支撑，本体外补充是否标注 |

图谱可生成性是覆盖度、传导完整度和本体调用一致性的必检子项，不新增独立顶层评分维度。评测时必须检查：

- 产业链方向是否能由 `segmentConnectsToSegment` 明确画出。
- 产品依赖、替代、互补或竞争是否能由 `productRelatesToProduct` 明确画出。
- 公司供应、代工、渠道、合作、竞争、投资控制或授权是否能由 `companyRelatesToCompany` 明确画出。
- 材料到产品用途是否能由 `materialUsedInProduct` 明确画出。
- 事件影响链是否能由 `eventAffectsVariable`、`eventRelatesToEvent` 或 `eventProducesObservation` 明确画出。

如果只能靠 `positionInChain`、对象描述或行业常识画图，应视为图谱可生成性不足，并在修复建议中点名缺失关系类型。

评分口径：

- 0：完全不具备。
- 1：只能泛泛回答。
- 2：有部分相关内容，但明显不完整。
- 3：基本能回答，但有明显缺口。
- 4：整体可用，有少量优化点。
- 5：完整、清晰、可解释、可验证、可复用。

## 2. 总分计算

单题分：

```text
question_score = average(8 dimension scores) / 5 * 100
```

加权总分：

```text
total_score = weighted_average(question_score, question_tier_weight * severity_weight * scope_type_weight)
```

默认严重度权重：

| severity | weight |
| --- | --- |
| `critical` | 1.35 |
| `high` | 1.20 |
| `medium` | 1.00 |
| `low` | 0.80 |

热点题默认不参与发布硬门槛，但参与 `practical_readiness_score`。若用户明确要求热点题作为发布场景，才把热点题转入核心题集合。

## 3. 单题通过标准

默认单题通过条件：

- 单题总分 >= 80。
- `ontology_consistency` >= 4。
- critical / high 题不得出现核心链条断裂。
- 关键维度不得低于 3；关键维度包括覆盖度、传导完整度、可验证性、本体调用一致性。

低于标准则为 `fail`，但热点题因 reference 不足失败时应标为 `insufficient_reference_support`，不能自动算 critical failure。

## 4. 硬门槛

默认发布硬门槛：

```yaml
total_score_min: 80
core_question_pass_rate_min: 0.80
critical_failure_count_max: 0
core_chain_break_count_max: 0
high_priority_gap_count_max: 0
verification_signal_coverage_min: 0.70
boundary_condition_coverage_min: 0.70
ontology_consistency_score_min: 0.80
```

硬门槛优先于平均分。只要存在 critical failure 或核心链条断裂，不能评为 A 或 B。

## 5. 发布等级

### A：通过

条件：

- 总分 >= 85。
- 核心问题通过率 >= 85%。
- 严重失败 = 0。
- 核心链条断裂 = 0。
- 高优先级缺口 = 0。
- 验证信号覆盖率 >= 75%。
- 边界条件覆盖率 >= 75%。
- 本体调用一致性 >= 85%。

输出 `allow_publish`。

### B：有条件通过

条件：

- 总分 >= 80。
- 核心问题通过率 >= 80%。
- 严重失败 = 0。
- 核心链条断裂 = 0。
- 高优先级缺口 = 0。
- 验证信号覆盖率 >= 70%。
- 边界条件覆盖率 >= 70%。
- 本体调用一致性 >= 80%。

输出 `conditional_publish`，并记录中低优先级优化项。

### C：不通过，修复后复评

出现以下任一情况：

- 总分 70-79。
- 核心问题通过率 60%-79%。
- 存在高优先级缺口。
- 部分关键问题回答不完整。
- 验证信号或边界条件明显不足。

输出 `reject_publish`。

### D：不通过，需要重大重构

出现以下任一情况：

- 总分 < 70。
- 核心问题通过率 < 60%。
- 存在严重链条断裂。
- 核心产业对象、核心状态变量或核心关系缺失。
- 大量回答脱离本体。
- 无法支撑目标投研场景。

输出 `reject_publish`。

### E：证据不足

出现以下任一情况：

- 评测问题过少。
- 评测问题类型严重不完整。
- reference 缺失且判断依赖外部事实。
- 本体输入结构严重缺失。
- 目标范围不清。
- 热点题为主且热点事实无法核验。

输出 `insufficient_evidence`。低可信度评测不能直接作为正式发布判断。

## 6. 严重失败

以下情况判定为严重失败：

- 核心评测问题无法回答。
- 核心产业对象、状态变量或传导关系缺失。
- 无法从事件推导到状态变量。
- 无法从状态变量推导到公司影响或资产影响。
- 没有任何验证信号。
- 完全缺少边界条件。
- 完全没有反证能力。
- 回答大量脱离本体。
- 结论与 reference 中的基本事实明显冲突。

只要存在严重失败，不能评为 A 或 B。

## 7. 评测可信度

- `high`：题量充足、题型完整、reference 充足、本体结构完整、评分依据清晰。
- `medium`：题量基本够用、reference 较少、部分题型覆盖不足，但能判断主要问题。
- `low`：题量过少、题型单一、没有 reference、本体结构不完整、目标范围不清或评分依据不足。

### 数据回灌对可信度的提升

当存在 `fetched_data` 且数据满足率达标时，评测可信度可按以下规则提升：

| 条件 | 提升路径 |
|------|----------|
| `data_sourcing_summary.fulfillment_rate >= 80%` | 可从 `medium` → `high`（最多提升一档） |
| `data_sourcing_summary.fulfillment_rate >= 50%` | 可从 `low` → `medium`（最多提升一档） |
| 高优先级数据项（priority=high）全部满足 | 额外获得 `data_backed_confidence` 标记 |

数据满足率不影响从 `low` → `medium` 的基础提升条件（仍需题量充足等），但满足率低于 30% 时，即使其他条件充足，评测可信度不得为 `high`。

## 8. 数据驱动评分锚定

当工作流 Step 3 接收到 `fetched_data` 回灌结果后，以下维度的评分口径在原标准基础上附加锚定规则：

### verifiability（可验证性）

```
当 fetched_data 中存在与某题目信号直接匹配的数据项时，该信号对应的 verifiability 维度得分自动不低于 3 分（"基本能回答，但有明显缺口"）。

当 fetched_data 覆盖该题目所有 required_ontology_elements 中涉及信号的 80%+ 时，verifiability 锚定下限为 4 分。

未覆盖到的信号仍按原 0-5 分标准评分，不因部分数据存在而整体锚定过高。

verification_signal_coverage 的计算中，有 fetched_data 支撑的信号计入 "data_backed_covered"，其余计入 "logic_only_covered"。
```

### boundary_conditions（边界条件）

```
当 fetched_data 提供了某边界触发场景的事实数据（如历史价格区间、政策节点日期等）时，boundary_conditions 维度中与数据匹配的边界条件自动不低于 3 分。

数据只能锚定"本体声称的边界是否与真实数据一致"，不能替代本体推理中缺失的边界条件判断。缺失的边界条件仍按 0 分处理。
```

### evaluation_confidence 与数据满足率

```
data_sourcing_summary.fulfillment_rate 作为评测元数据的一部分，在发布判定中逐次生效：

- fulfillment_rate >= 70%：数据支撑充分，评测可信度可酌情提升
- 30% <= fulfillment_rate < 70%：数据部分支撑，评测可信度保持原级或数据锚定升级
- fulfillment_rate < 30%：数据缺口较大，verifiability 和 boundary_conditions 若成为阻断因素，发布判定自动降级一档（如 A→B、B→C），并在 threshold_check 中标注降级原因为 data_gap
```

### hotspot 题的数据驱动增强

```
hotspot 题中已由 fetched_data 覆盖的数据项：
- hotspot_source_status 自动为 fully_traceable
- 该类题目不标记为 insufficient_reference_support
- practical_readiness_score 计算中此类题目的权重按已完成核验处理
```

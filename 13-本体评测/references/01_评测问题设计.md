# 评测问题设计

## 1. 四层问题集

评测问题采用“固定基准题 + 本体类型题 + 新闻热点题 + 挑战题”。

| `question_tier` | 说明 | 默认权重 | 规则 |
| --- | --- | --- | --- |
| `baseline` | 版本间固定题，测试共同核心能力 | 1.20 | 必须参与发布硬门槛 |
| `type_specific` | 按本体类型选择或生成 | 1.15 | 必须覆盖本体类型主能力 |
| `hotspot` | 近期新闻、政策、公告、价格、订单、技术变化压力题 | 0.85 | 默认不单独决定发布 |
| `challenge` | 半随机挑战题，防止过拟合 | 1.00 | 必须可解释生成依据 |

建议题量：

- 最小评测：8-12 题。
- 标准评测：15-25 题。
- 重要发布版本：25-40 题，并包含热点题和挑战题。

题量低于 8、六类能力覆盖严重不足、或 reference 缺失且判断依赖外部事实时，评测可信度只能为 `low`，必要时输出 `insufficient_evidence`。

## 2. 六类能力题

每套题至少覆盖以下六类能力：

| `question_type` | 测试能力 |
| --- | --- |
| `event_impact` | 从事件推导到对象、变量、产业链、公司和资产影响 |
| `industry_chain_transmission` | 表达上下游传导、方向、机制、节奏和滞后 |
| `company_benefit` | 从产业变化推导公司层面的差异化受益或受损 |
| `risk_falsification` | 识别反向变量、逻辑失效、阻断条件和风险传导 |
| `state_monitoring` | 给出可跟踪、可证实、可证伪的信号和指标 |
| `asset_revaluation` | 从事件、变量、基本面、预期差和验证信号推导资产影响逻辑 |

## 3. 七类本体题型权重

| `scope_type` | 重点题型 | 题型权重建议 |
| --- | --- | --- |
| `industry` | 行业格局、景气变量、供需价格、资产重估 | `event_impact=1.10`、`state_monitoring=1.15`、`asset_revaluation=1.10` |
| `supply_chain` | 上下游传导、瓶颈环节、利润转移、滞后效应 | `industry_chain_transmission=1.35`、`risk_falsification=1.10` |
| `product_track` | 技术替代、渗透率、成本曲线、材料设备依赖 | `industry_chain_transmission=1.15`、`state_monitoring=1.20`、`risk_falsification=1.15` |
| `company_research` | 业务结构、收入利润驱动、差异化、兑现验证 | `company_benefit=1.35`、`state_monitoring=1.15`、`asset_revaluation=1.15` |
| `policy_theme` | 政策对象、执行节奏、受益受损主体、失效条件 | `event_impact=1.20`、`risk_falsification=1.20` |
| `macro_theme` | 宏观变量到行业/资产传导、周期性与结构性区分 | `industry_chain_transmission=1.15`、`risk_falsification=1.20`、`asset_revaluation=1.10` |
| `event_theme` | 事件识别、冲击范围、短中长期影响、情景分叉 | `event_impact=1.35`、`risk_falsification=1.15` |

权重用于加权总分和题集设计，不允许用权重掩盖关键链条断裂。

## 4. 单题结构

每道题建议包含：

```json
{
  "question_id": "",
  "question_tier": "baseline/type_specific/hotspot/challenge",
  "question_type": "event_impact",
  "question_text": "",
  "target_capability": "",
  "expected_reasoning_elements": [],
  "required_ontology_elements": [],
  "severity_if_failed": "low/medium/high/critical",
  "reference_ids": [],
  "generation_basis": "",
  "hotspot_source_refs": []
}
```

`generation_basis` 必须说明题目来源：固定基准、类型模板、新闻热点、半随机组合或用户指定。

## 5. 新闻热点题规则

新闻热点题用于测试真实投研场景，不替代固定基准题。

生成标准：

- 默认时间窗口为近 90 天；用户可用 `news_hotspot_config.recency_days` 设置为 30-90 天或其他明确窗口。
- 题目必须来自可追溯来源：公告、财报、政策原文、监管/交易所、行业协会、公司发布、可靠新闻或可追溯研报。
- 涉及最新政策、价格、订单、技术变化、公司动态或市场数据时，执行者必须检索或核验来源，并记录 `hotspot_source_refs`。
- 热点题应命中本体核心对象、核心变量、核心传导链或目标范围内的重要边界。
- 无法核验事实的热点题标记 `insufficient_reference_support`，不能作为 critical failure。
- 热点题默认只影响 `practical_readiness_score`、评测可信度和修复建议；只有用户明确把热点题列为核心发布场景时，才参与硬门槛。

数据回灌增强规则：

- **优先使用 fetched_data**：当输入中存在 `fetched_data` 时，热点题优先从已获取数据中提取具体题面（如带日期的公告标题、带数值区间的价格变化、有明确来源的政策名称），替代抽象的「近期政策变化」「最新价格波动」类泛化题面。
- **自动标记可核验**：数据 Skill 已提供的可追溯来源自动标记为 `hotspot_source_status=verified`，热点题的可信度从 `partially_traceable` 提升为 `fully_traceable`。
- **退回到检索**：fetched_data 不足以覆盖所有热点题时，剩余热点题退回到执行者自行检索或使用用户 reference；仍无法核验的按标准规则标记。
- **热点题不得绕过数据清单**：如果工作流 Step 2 已生成 `data_requirements_checklist`，热点题应优先使用其中的 `event` 和 `timeline` 类型数据项；数据清单中未覆盖的热点方向需在 `hotspot_source_refs` 中说明数据来源差异。

不得把短期新闻直接当作稳定本体逻辑。热点题触发的修复项必须进入候选优化、证据补充或 backlog。

## 6. 半随机挑战题规则

挑战题可以随机组合题面，但不能随机评测目标。

有效挑战题必须满足：

- 命中至少一个本体核心对象或状态变量。
- 覆盖一个明确的 `question_type`。
- 能列出 `expected_reasoning_elements`。
- 能映射到 `required_ontology_elements` 或明确指出待检索元素。
- 不超出 `target_scope` 的合理边界。
- 生成依据可复核，必要时记录随机种子或选择规则。

挑战题常用组合：

- 核心事件 + 非核心链条。
- 核心变量反向变化 + 公司差异化影响。
- 上游冲击 + 下游价格无法传导。
- 热点事实 + 本体边界条件。
- 市场预期变化 + 兑现信号。

## 7. 问题集可信度

`question_set_quality` 建议取：

- `high`：题量充足，四层题目合理，六类能力完整，七类本体权重匹配，reference 足够。
- `medium`：题量基本够用，少量题型或 reference 不足，但能判断主要问题。
- `low`：题量不足、题型单一、热点题无法核验、目标范围不清或本体类型不明。

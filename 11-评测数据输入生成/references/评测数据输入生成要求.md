# 评测数据输入生成要求

本文件定义如何为评测 Skill 准备输入材料、数据需求和交接说明。本 Skill 只做评测前数据准备或评测后数据回补，不做评分、发布判断或本体修改。

## 1. 运行模式

| 模式 | 触发 | 主要输出 |
|---|---|---|
| A 主题预备 | 尚无候选本体，只有研究主题或冷启动任务 | 评测题源材料、热点材料、基础数据需求。 |
| B 本体驱动 | 已有 `ontology_bundle_vN/` | 围绕本体概念、对象、关系、变量、传导和信号生成完整评测输入。 |
| C 评测后回补 | 评测 Skill 返回数据缺口或补充请求 | 针对缺口补充数据和来源，回写交接说明。 |

默认使用模式 B。若多个模式条件同时满足，以用户明确要求优先；否则按 C、B、A 顺序选择。

## 2. 模式边界

### 模式 A：主题预备

用于提前准备评测材料。不得声称材料已经对应某个本体。输出需标明“待本体生成后复核”。

### 模式 B：本体驱动

读取候选本体 bundle，围绕概念、对象、关系、状态变量、传导链、信号、情景和未解决问题准备评测材料。不得修正本体内容；发现本体缺字段时写入 `docs/evaluation_handoff.md`。

### 模式 C：评测后回补

只处理评测 Skill 点名的数据缺口。不得重新评测，不得改变原评测结论，只交付补充材料和来源。

## 3. 输入展开

优先读取：

1. `ontology_bundle_vN/` 中的概念层、研究范围、对象、关系、变量、传导、信号、情景、资产线索。
2. `docs/production_notes.md` 中的优化目标、证据限制和 remaining gaps。
3. `_artifacts/sources/source_material_summary.md` 中的来源可靠性和使用限制。
4. `_artifacts/evidence_graph/` 中的 EvidenceEpisode、EvidenceClaim、EvidenceFact、失效候选和证据限制。
5. `_artifacts/patches/patch_ledger.yaml` 中的增量合并、拒绝、延后和失败记录。
6. `_artifacts/reasoning_runs/` 中的推理运行样本。
7. `07_governance.yaml` 与 `08_optimization_handoff.yaml` 中的未解决数据需求。
8. `source_registry.json` 和 `source_materials/` 中的原始来源。

冲突时，以候选本体为评测主体，以来源摘要解释证据限制。

## 4. `_artifacts/evaluation_results/evaluation_data_inputs/`

建议结构：

```
_artifacts/evaluation_results/evaluation_data_inputs/
  evaluation_scope.md
  eval_question_source_materials.md
  hotspot_materials.md
  ontology_signal_data_requirements.json
  fetched_data_registry.json
  evidence_graph_input.yaml
  patch_ledger_input.yaml
  inference_run_samples.yaml
  unresolved_data_requirements.md
  source_index.md
```

| 文件 | 内容 |
|---|---|
| `evaluation_scope.md` | 评测范围、版本、scope_type、模式和限制。 |
| `eval_question_source_materials.md` | 可用于生成 baseline/type_specific/challenge 题的材料。 |
| `hotspot_materials.md` | 近期事件、政策、公告、价格、订单和技术变化材料。 |
| `ontology_signal_data_requirements.json` | 从本体变量、信号、边界条件提取的数据需求。 |
| `fetched_data_registry.json` | 已获取数据及来源。没有数据时为空数组并说明。 |
| `evidence_graph_input.yaml` | 供评测检查 episode 覆盖、claim 追溯、失效过滤和受限证据的输入。 |
| `patch_ledger_input.yaml` | 供评测检查 patch 审计、合并理由和拒绝项的输入。 |
| `inference_run_samples.yaml` | 供评测检查推理运行记录完整性的样本。 |
| `unresolved_data_requirements.md` | 未满足的数据需求和影响。 |
| `source_index.md` | 所有来源 ID、标题、路径、可靠性和使用限制。 |

`evaluation_scope.md` 必须说明 `01_concepts.yaml` 中的 in_scope、out_of_scope、adjacent、overlap 和 disputed 概念，作为评测题目纳入/排除的边界依据。

## 5. 数据需求生成

每条数据需求包含：

| 字段 | 要求 |
|---|---|
| `data_item_id` | 稳定 ID。 |
| `data_type` | `signal`、`indicator`、`event`、`timeline`、`fact`。 |
| `mapped_ontology_element` | 对应对象、变量、信号、传导或情景。 |
| `search_keywords` | 检索关键词。 |
| `date_range` | 时间范围。 |
| `priority` | P0/P1/P2。 |
| `expected_use` | 用于可验证性、边界条件、热点题或事实核验。 |
| `minimum_source_level` | high/medium/low。 |
| `status` | fulfilled/unfulfilled/partial。 |

缺少显式信号时，可根据状态变量和传导链推断最低必要数据需求，但必须标记 `inferred=true`。

## 6. 热点材料

热点材料用于压力测试，不直接决定发布。涉及近期、最新、政策、公告、价格、订单或公司动态时，必须记录：

- 事件标题。
- 发布时间。
- 业务时间。
- 来源 ID 和位置。
- 涉及对象和变量。
- 可用于哪类评测题。
- 是否已核验。

无法核验的热点只能作为低置信题源，不能作为 critical failure 依据。

## 7. `docs/evaluation_handoff.md`

交接说明必须包含：

1. 本轮运行模式和输入文件。
2. 候选本体版本、范围和评测主体。
3. 可用材料清单和来源可靠性。
4. 数据需求满足情况。
5. 未解决数据缺口及其对评测维度的影响。
6. Evidence graph、patch ledger 和 inference run 是否可用于评测，以及缺失限制。
7. 禁止事项和使用边界。

交接说明可以给评测 Skill 提醒，但不得替评测 Skill 打分或判定发布。

## 8. 质量门槛

| 检查项 | 通过标准 |
|---|---|
| 模式清楚 | A/B/C 选择和理由明确。 |
| 本体绑定 | 模式 B 中材料能映射到本体对象、变量或信号。 |
| 来源可追溯 | 题源、热点和数据均有来源 ID。 |
| Evidence 可评测 | 若存在 evidence graph，episode/claim/fact/失效候选能被评测输入引用。 |
| Patch 可审计 | 若存在 patch ledger，合并、拒绝、延后和失败记录可追溯。 |
| 推理运行样本 | 若存在 reasoning runs，样本不含隐藏评测答案或投资建议。 |
| 缺口显性 | 未满足数据需求和影响写清。 |
| 不越权 | 无评分、发布判断、优化任务或本体修改。 |

## 9. 禁止事项

- 不输出 `allow_publish`、`conditional_publish`、`reject_publish` 或 `insufficient_evidence`。
- 不输出逐题评分或维度评分。
- 不输出 `evaluation_fix_report`、`optimization_plan` 或优化建议。
- 不修改评测集，不修改候选本体。
- 不把无法核验热点当作关键事实。

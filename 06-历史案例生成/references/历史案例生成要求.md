# 历史案例生成要求

本文件定义如何为历史回放校验生成真实、可追溯、可复盘的历史案例材料。本 Skill 只准备案例，不执行本体回放，不判断本体通过与否。

## 1. 案例选择目标

历史案例必须服务于本体有效性校验，而不是证明某个观点正确。样本集应覆盖成功、失败、边界和留出场景，使历史回放 Skill 能检验传导链、变量口径、阻断条件、时间滞后和资产影响边界。

## 2. 案例类型

| 类型 | 定义 | 用途 |
|---|---|---|
| `positive_trigger` | 本体链路理论上应被触发，后续结果也基本支持的案例 | 检查链路是否能命中正向触发。 |
| `negative_failure` | 看似应触发但实际未兑现或方向相反的案例 | 检查是否缺阻断条件和竞争解释。 |
| `boundary_case` | 处在阈值、时滞、地域、主体或政策边界附近的案例 | 检查适用范围和变量颗粒度。 |
| `holdout_case` | 未参与本体构建、独立用于验证的案例 | 检查泛化能力。 |

每个样本集至少覆盖四类案例各 1 个。做不到时，报告必须说明原因和影响。

## 3. 入选标准

案例应满足：

- 事件或状态变化有明确 t0。
- t0 当时可得信息可追溯。
- t0 后有可验证结果。
- 与研究主题、变量、传导链或缺口任务有关。
- 不仅选择支持既有假设的样本。

以下案例应谨慎使用或剔除：

- 只有二手摘要且无法追溯原文。
- 事件时间、结果时间或主体不清。
- 结果完全不可验证。
- 主要信息来自目标价、评级、推荐语或仓位表达。
- 与研究主题关系过弱，只能凑数量。

## 4. t0 确定规则

t0 是历史回放开始判断的业务时点。确定顺序：

1. 公告、政策、财报、交易所文件的发布时间。
2. 事件首次被可靠来源披露的时间。
3. 数据指标达到触发阈值的时间。
4. 若多个时间点合理，选择最早可被普通研究员获得的信息时点，并说明备选 t0。

t0 不一定等于结果验证时间。t0 后披露的信息只能进入结果包，不能进入 t0 信息包。

## 5. t0 信息包

每个案例目录至少包含：

```
historical_materials/
  CASE-001/
    case_brief.md
    t0_information.md
    post_t0_outcome.md
    source_index.md
```

`t0_information.md` 必须列出：

- t0 时间。
- t0 当时可获得的信息。
- 信息来源、页码、链接或原文位置。
- 当时尚不可获得的信息。
- 基于 t0 信息可提出的回放问题。
- 防事后信息泄漏说明。

## 6. t0 后结果包

`post_t0_outcome.md` 记录验证窗口内真实结果：

- 结果时间窗口。
- 实际事件、数据变化或业务结果。
- 与 t0 预期可能一致、相反或未兑现的部分。
- 混杂因素和替代解释。
- 来源和可靠性。

结果包用于校验，不得倒灌到 t0 信息包。

## 7. 覆盖维度

选择案例时尽量覆盖：

| 维度 | 例子 |
|---|---|
| 事件类型 | 政策、公告、价格变化、订单、事故、制裁、并购。 |
| 变量方向 | 上升、下降、持平、波动、延迟。 |
| 链条位置 | 上游、中游、下游、客户、资产端。 |
| 主体类型 | 行业、公司、产品、材料、政策主体。 |
| 时间阶段 | 周期早期、中期、后期、拐点。 |
| 结果类型 | 兑现、未兑现、反向兑现、延迟兑现。 |
| 证据质量 | 高、中、低可靠来源。 |
| 本体用途 | 传导、阻断、情景、资产影响、证据追溯。 |

## 8. `historical_case_generation_report.md`

报告必须包含：

1. 研究主题和案例选择范围。
2. 案例清单和四类样本覆盖。
3. 每个案例的 t0、验证窗口、来源和入选理由。
4. t0 冻结方法和防泄漏说明。
5. 样本偏差、缺失案例和材料限制。
6. 给历史回放 Skill 的使用建议。

## 9. `replay_task_list.md`

每条任务写清：

| 字段 | 要求 |
|---|---|
| `task_id` | 稳定 ID。 |
| `case_id` | 对应案例。 |
| `case_type` | 四类之一。 |
| `focus_assertion` | 希望校验的本体断言或链路。 |
| `t0_available_inputs` | t0 可用材料清单。 |
| `validation_window` | 验证窗口。 |
| `expected_check` | 希望历史回放回答的问题。 |
| `source_refs` | 来源引用。 |
| `leakage_guardrail` | 防泄漏提示。 |

## 10. 质量门槛

| 检查项 | 通过标准 |
|---|---|
| 四类覆盖 | 正向、反向、边界、留出均有样本，或明确说明缺失。 |
| t0 可追溯 | t0 信息有来源和位置。 |
| 结果可验证 | t0 后结果有验证窗口和来源。 |
| 防泄漏 | t0 信息和后验结果分离。 |
| 样本不偏 | 不只选择支持观点的案例。 |

## 11. 禁止事项

- 不执行本体回放，不判断本体健康度。
- 不输出 `historical_cases.json`，该结构由历史回放 Skill 生成。
- 不把后验结果写进 t0 信息包。
- 不把目标价、评级、推荐语、收益率预测或仓位表达作为事实观测。

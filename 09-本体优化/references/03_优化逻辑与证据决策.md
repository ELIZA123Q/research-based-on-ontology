# 优化逻辑与证据决策

本文件定义已有本体的优化方式。内容覆盖 `scope_type` 判定、七类 playbook、证据标准、优化动作和下一轮计划生成。本文不描述其他 Skill 或数据流。

## 1. 优化原则

- `optimization_plan` 是本轮优化的主依据。计划已指定目标缺口、材料方向、证据门槛或建议动作时，playbook 只补充诊断顺序、证据判断和输出字段映射。
- playbook 是优化镜头，不是固定答案。本轮只优化证据可得、价值最高、能够闭环的 1-3 个缺口。
- 结构变化由证据驱动。新增、更新、强化、保留、废弃和拒绝动作均需要证据主张、计划依据或诊断依据。
- 候选内容以保留为默认处理。未被反证的对象、关系和推理链应规范化迁移并降级保留。
- 拒绝条件包括违反 schema、端点无法成立、证据不可追溯和越过交易建议边界。
- 事实观测、状态变量和关系端点是资产线索的前置依据。资产影响保持为线索或候选，不升级为投资结论。

## 2. 通用优化闭环

每轮优化按以下结果链组织。证据不足的环节降级保留，并写入 `next_optimization_plan`。

| 顺序 | 结果项 | 输出落点 |
|---|---|---|
| 1 | 本体基座、计划目标和高召回候选层完成识别 | `base_ontology_assessment`、`current_optimization_goal` |
| 2 | 本轮 `scope_type` 和 playbook 完成选择 | `selected_playbook` |
| 3 | 对象真实性、对象边界和来源追溯完成校验 | `objects`、`source_documents`、`unresolved_objects` |
| 4 | 关系端点、方向、层级和约束完成校验 | `relations`、`unresolved_relations` |
| 5 | 状态变量口径、单位、时间范围和可观测数据完成补充 | `state_variables`、`state_observations` |
| 6 | 事件、变量、滞后窗口、传导路径和阻断条件完成表达 | `propagation_templates`、`hypotheses`、`blocking_conditions` |
| 7 | 支持信号、削弱信号、跟踪信号和反证条件完成补充 | `signals`、`scenario_paths`、`missing_evidence` |
| 8 | 市场预期、估值锚和定价状态形成资产线索 | `asset_impact_clues`、`asset_impacts` |
| 9 | 证据状态、允许字段、禁止字段和优化动作完成记录 | `optimization_changes`、`optimization_decision_basis` |
| 10 | 剩余缺口、材料要求、证据门槛和停止条件形成下一轮计划 | `next_optimization_plan` |

业务结构图谱关系是第 4 步的必检项。优化时必须检查 `segmentConnectsToSegment`、`companyRelatesToCompany`、`productRelatesToProduct`、`materialUsedInProduct`、`materialRelatesToMaterial`、`assetExposedToTarget`、`eventRelatesToEvent`、`eventAffectsVariable`、`eventProducesObservation` 和 `judgmentRelatesToJudgment` 是否能承接当前材料中的业务连接。证据不足时不要用描述字段补边，写入 `unresolved_relations` 和下一轮计划。

## 3. scope_type 判定

本体中的 `ontology_scope.scope_type` 是默认依据。缺失或与本轮计划不一致时，按缺口、对象、变量和研究问题判定，并将取舍写入 `selected_playbook.selection_basis`。

| scope_type | 适用条件 | 排除条件 |
|---|---|---|
| `industry` | 行业边界、环节结构、周期变量、竞争格局、政策变量或行业资产暴露是核心缺口 | 研究中心是单家公司、单个产品或单次事件 |
| `supply_chain` | 上下游端点、瓶颈环节、库存、产能、订单、成本转嫁或利润分配是核心缺口 | 缺少明确环节关系，只有宏观变量或政策方向 |
| `product_track` | 产品定义、技术路线、认证审批、竞品替代、客户采用或渗透率是核心缺口 | 产品只是公司业务线的从属字段，核心缺口是公司财务兑现 |
| `company_research` | 公司业务线、客户订单、产能项目、收入、毛利、费用、现金流或资产锚点是核心缺口 | 没有具体公司，或公司只是行业样本 |
| `policy_theme` | 政策原文、监管工具、财政补贴、审批机制、执行口径或受益/受损对象是核心缺口 | 只有媒体解读或概念方向，缺少政策工具 |
| `macro_theme` | 利率、汇率、信用、通胀、流动性、财政、贸易、行业暴露或资产敏感性是核心缺口 | 核心变量来自单一产业内部，而非宏观口径 |
| `event_theme` | 突发事件、制裁、事故、停产、监管处罚、供给扰动或修复路径是核心缺口 | 事件只是背景，核心缺口是长期行业或公司结构 |

> **兼容输入**：非标准值 `uncertain` 或旧字段 `ontology_type`（如 `product_technology`）只能作为兼容输入读取，不得直接作为 playbook 选择的依据。`uncertain` 必须根据 `industry_context` 和缺口特征推断至上述 7 种标准值之一，并记录到 `selected_playbook.selection_basis`。`product_technology` 映射为 `product_track`。

多个类型同时命中时，`optimization_plan.target_gaps` 中最需要动作决策的缺口作为主类型，其他类型作为辅助视角。

## 4. 七类 playbook

### industry

- `playbook_id`: `industry_structure_cycle_competition_policy_v1`
- 适用结果：行业边界、结构、周期变量、竞争变量、政策变量和行业资产暴露完成证据化表达。
- 优化落点：行业边界和核心环节；供需、价格、库存、产能等状态变量；政策、竞争格局和历史样本；资产暴露线索、市场预期和反证条件。
- 材料来源：行业协会或监管数据、政策原文、龙头公司年报、价格/产能/库存数据、竞争格局资料。
- 证据标准：官方或行业协会材料支持行业结构和政策事实；可追溯数据支持变量观测；公司公告或财报支持资产暴露线索。
- 输出字段：`objects` 中的 `Industry`、`Segment`、`Company`、`Asset`，以及 `relations`、`state_variables`、`state_observations`、`propagation_templates`、`signals`、`asset_impact_clues`。
- 降级/拒绝：宽泛主题词、无原始来源的行业规模、无法映射到环节的变量、从行业变化直接跳到资产结论。

### supply_chain

- `playbook_id`: `supply_chain_bottleneck_margin_v1`
- 适用结果：上下游端点、瓶颈环节、量价库存产能、成本转嫁和利润分配完成证据化表达。
- 优化落点：上下游端点和关系方向；价格、库存、产能、订单和交付变量；成本转嫁、利润分配和滞后窗口；阻断条件和修复信号。
- 材料来源：上下游公告、价格数据、订单/招投标、库存/产能数据、海关或出货数据。
- 证据标准：端点关系由公司公告、采购/销售披露或产业数据支持；量价库存由可复核数据支持；传导链由跨期证据或历史样本支持。
- 输出字段：`objects` 中的 `Company`、`Segment`、`Product`、`Material`，以及 `relations`、`state_variables`、`state_observations`、`propagation_templates`、`blocking_conditions`、`signals`。
- 降级/拒绝：只有单方口径、上下游端点不清、价格上涨直接等同利润改善、缺少库存/产能约束。

### product_track

- `playbook_id`: `product_track_commercialization_v1`
- 适用结果：产品定义、技术路线、认证审批、客户采用、商业化进度和渗透率完成证据化表达。
- 优化落点：产品边界和技术路线；认证、审批、试验和量产进度；客户采用、竞品替代、价格和渗透率；商业化阻断条件。
- 材料来源：产品手册、认证/审批文件、专利、临床/试验材料、客户采购、竞品对比、价格和渗透率数据。
- 证据标准：官方、认证或审批材料支持产品存在和进度；采购、订单或公告支持客户采用；可追溯数据支持渗透率或价格观测。
- 输出字段：`objects` 中的 `Product`、`Company`、`Segment`，以及 `relations`、`state_variables`、`state_observations`、`propagation_templates`、`signals`、`scenario_paths`。
- 降级/拒绝：概念产品无商业证据、技术路线无验证、研发进展直接等同收入兑现、竞品替代关系无可比条件。

### company_research

- `playbook_id`: `company_business_financial_chain_v1`
- 适用结果：公司产业暴露、产品暴露、事件暴露、订单兑现、产能兑现和财务观测完成证据化表达。
- 优化落点：业务线、产品和产业链位置；客户、订单、项目和产能；收入、毛利、费用、现金流等财务观测；市场预期、估值锚和定价状态线索。
- 材料来源：年报、季报、招股书、业务拆分、客户订单、产能建设、费用率、毛利率、现金流、市场预期材料。
- 证据标准：公告或财报支持业务和财务口径；订单或采购证据支持兑现路径；市场材料只支持资产线索，不替代经营观测。
- 输出字段：`objects` 中的 `Company`、`Product`、`Segment`、`Asset`，以及 `relations`、`state_variables`、`state_observations`、`propagation_templates`、`asset_impact_clues`。
- 降级/拒绝：只写公司档案、业务线无法对应财务口径、单期财务变化直接推出拐点、主题概念等同公司真实暴露。

### policy_theme

- `playbook_id`: `policy_tool_implementation_v1`
- 适用结果：政策原文、政策工具、执行机制、影响对象、落地信号和阻断条件完成证据化表达。
- 优化落点：政策主体、原文和工具类型；资金、审批、监管、补贴和约束机制；受益/受损对象和企业响应；执行信号、阻断条件和反证路径。
- 材料来源：政策原文、部委解读、地方执行文件、财政/补贴/审批数据、企业响应公告。
- 证据标准：政策事实由原文支持；落地机制由执行文件或数据支持；企业影响由公告、订单或经营观测支持。
- 输出字段：`events`、`relations`、`state_variables`、`state_observations`、`propagation_templates`、`signals`、`blocking_conditions`，以及受影响的 `Industry`、`Segment`、`Company`、`Product` 对象。
- 降级/拒绝：只引用媒体解读、政策工具不明确、政策方向直接等同企业受益、缺少执行口径。

### macro_theme

- `playbook_id`: `macro_variable_asset_transmission_v1`
- 适用结果：宏观变量口径、滞后窗口、行业暴露、资产敏感性、市场定价和历史样本完成证据化表达。
- 优化落点：宏观变量口径、频率和来源；行业暴露和传导路径；滞后、反身性和历史样本；资产敏感性、市场预期和反证信号。
- 材料来源：央行、统计局、海关、财政数据，利率、汇率、信用、行业高频数据和资产价格材料。
- 证据标准：宏观变量由官方或权威数据支持；行业暴露由可追溯数据支持；资产影响由市场定价和历史样本共同支持。
- 输出字段：`state_variables`、`state_observations`、`objects` 中的 `Industry`、`Segment`、`Asset`，以及 `relations`、`propagation_templates`、`signals`、`scenario_paths`、`asset_impact_clues`。
- 降级/拒绝：单一宏观指标外推行业结论、忽略滞后和反身性、把资产价格当基本面证据。

### event_theme

- `playbook_id`: `event_impact_repair_path_v1`
- 适用结果：事件事实、影响对象、短中长期传导、修复路径、历史类比和反证信号完成证据化表达。
- 优化落点：事件来源、发生时间和事实边界；受影响对象和影响链条；持续时间、修复路径和历史类比；反证信号和情景路径。
- 材料来源：原始事件来源、受影响对象公告、监管或新闻原文、历史类比案例、修复进展、反证信号。
- 证据标准：事件事实由原始来源支持；影响对象由公告或权威披露支持；历史类比包含可比条件说明。
- 输出字段：`events`、`objects`、`relations`、`propagation_templates`、`signals`、`blocking_conditions`、`scenario_paths`。
- 降级/拒绝：事件来源不清、影响对象泛化、历史类比条件不同、短期扰动直接写成长周期判断。

## 5. 证据到动作决策

| 证据状态 | 允许写入 | 禁止写入 | 默认动作 |
|---|---|---|---|
| 无来源或只有上游候选 | 缺口、候选对象、下一轮材料计划 | 事实观测、确认关系、正式判断 | `keep` 或 `deprecate` |
| 单一非官方来源 | 搜索线索、弱强化、候选假设 | `StateVariableObservation`、确认关系、资产影响判断 | `keep` 或 `strengthen` |
| 单一官方/公告/财报/政策原文 | 事实对象、事实观测候选、口径修正 | 趋势确认、完整传导确认、投资结论 | `add` 或 `update` |
| 多个独立来源一致 | 传导模板强化、信号强化、状态变量口径更新 | 人工确认状态、目标价、交易建议 | `strengthen` 或 `update` |
| 明确反证或端点错误 | 反证记录、废弃原因、未解析项 | 原候选继续升级 | `deprecate` 或 `reject` |

动作选择规则：

- `add` 用于符合 schema 且具备可追溯来源或明确计划依据的新增项。
- `update` 用于修正证据覆盖范围内的字段。
- `strengthen` 用于证据支持已有链路但不足以确认的项目。
- `keep` 用于本轮不处理、证据不足但未被反证的候选。
- `deprecate` 用于口径过粗、证据不足、范围错误或存在部分反证的候选。
- `reject` 用于明确不成立、违反 schema、无法追溯或越过交易建议边界的项目。

## 6. 下一轮计划生成

本轮不能完成升级时，剩余缺口转成可执行计划。

| 未完成原因 | 下一轮计划内容 |
|---|---|
| 对象真实存在但边界不清 | 边界定义、官方分类、业务拆分或产品说明 |
| 关系端点不清 | 公告、采购/销售披露、上下游数据或端点验证材料 |
| 业务结构图谱关系不清 | 上下游端点、公司供销/合作/竞争材料、产品依赖/替代材料、材料用途、事件影响变量证据 |
| 状态变量缺口径 | 变量口径、单位、频率、时间范围和推荐数据源 |
| 事实观测缺证据 | 原始公告、财报、政策原文、监管数据或可追溯数据库 |
| 传导链缺验证 | 历史样本、跨期数据、滞后窗口、支持/削弱信号 |
| 资产线索缺市场预期 | 市场预期材料、估值锚、定价状态和反证条件 |

`next_optimization_plan` 包含目标缺口、建议材料、最低证据等级、建议动作、停止/继续条件和预期质量变化。

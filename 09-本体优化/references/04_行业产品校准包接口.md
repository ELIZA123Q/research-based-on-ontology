# 行业产品校准包接口

## 1. 定位

行业产品校准包是本体优化 Skill 的行业校准规则，不是成熟本体、事实库或图谱生成器。

它只回答三类问题：

- 当前行业或产品赛道中，哪些材料更适合用来验证对象、关系、变量和传导。
- 哪些常见误判需要降级、剔除或转为下一轮材料缺口。
- 哪些业务结构关系在该行业中通常需要检查，但是否写入本体必须以本轮材料、基座对象和核心 schema 为准。

校准包不得直接提供未经本轮材料验证的公司事实、市场份额、盈利结论、资产判断、买卖建议、目标价、收益率预测或仓位建议。

## 2. 适用边界

优化 Skill 命中行业校准包时，必须先读取本接口，再读取具体行业包。

使用顺序：

1. 根据 `base_ontology.ontology_scope`、`industry_context`、对象名称、产品名称、环节名称和任务单判断是否命中行业包。
2. 读取行业包中的适用范围、优先证据源、专业变量、专业传导检查、常见误判和关系补齐检查。
3. 将行业包规则映射到核心对象与关系 schema。
4. 对证据充分的关系执行 `add`、`update` 或 `strengthen`。
5. 对证据不足、端点不清或语义属性不清的关系写入 `unresolved_relations`、`remaining_gaps` 和 `next_optimization_plan`。

未命中行业包时，使用通用优化逻辑，不得临时编造行业专有规则。

## 3. 与核心本体的关系

核心规范定义跨行业通用对象和关系。行业校准包只能提供行业级检查镜头，不能扩展核心 schema。

业务结构图谱关系必须使用核心规范中的通用关系：

| 业务问题 | 核心关系 |
| --- | --- |
| 产业链环节上下游、替代、互补或竞争 | `segmentConnectsToSegment` |
| 公司供应、代工、渠道、合作、竞争、投资控制或授权 | `companyRelatesToCompany` |
| 产品依赖、替代、互补、代际、部件、集成、竞争或使能 | `productRelatesToProduct` |
| 材料具体用于某产品 | `materialUsedInProduct` |
| 材料替代、前驱、伴生、工艺互补或产能竞争 | `materialRelatesToMaterial` |
| 资产暴露到产业、环节、公司、产品或材料 | `assetExposedToTarget` |
| 事件之间的触发、使能、缓解、反向或共现 | `eventRelatesToEvent` |
| 事件影响状态变量 | `eventAffectsVariable` |
| 事件产生或对应某条观测 | `eventProducesObservation` |
| 判断之间依赖、替代、细化、更新或冲突 | `judgmentRelatesToJudgment` |

关系类型负责端点类型；关系属性负责具体语义。行业包只能建议应检查哪类关系，不能用自然语言描述替代关系实例。

## 4. 关系补齐决策

每个候选关系按以下规则处理：

| 条件 | 处理 |
| --- | --- |
| 源对象、目标对象和关系语义均清楚，且有可追溯材料支持 | 写入 `relations`，`recordStatus=candidate` 或沿用基座状态 |
| 端点清楚但证据不足 | 写入 `unresolved_relations` 和 `next_optimization_plan` |
| 端点缺失 | 先写入 `unresolved_objects` 或对象材料缺口，不创建关系 |
| 关系方向不清 | 不创建关系；在材料缺口中要求补充采购/销售/合同/产品说明等材料 |
| 只有行业常识或模板假设 | 最高只能作为候选缺口，不得升级为确认关系 |
| 关系违反核心 schema 或越过投资建议边界 | `reject` 或写入人工审核项 |

## 5. 行业包最低结构

每个具体行业包应至少包含：

- 包元信息：`industry_pack_id`、`applicable_scope`、`keywords`。
- 边界：覆盖范围和排除范围。
- 优先证据源：材料类型、用途、可支持对象/动作。
- 专业状态变量：变量、口径、频率、来源、边界。
- 专业传导检查：传导链、验证材料、滞后/边界。
- 业务结构关系补齐检查：行业中需要优先检查的对象连接。
- 常见误判：需要降级、剔除或人工审核的模式。
- 降级/剔除规则：证据不足或越界时的默认处理。

## 6. 输出要求

使用行业校准包后，`optimization_report` 应能回答：

- 本轮命中了哪个行业包，命中依据是什么。
- 哪些校准规则被采用，哪些被跳过。
- 哪些业务结构关系被新增、修正、保留、降级或拒绝。
- 哪些关系因证据不足进入 `unresolved_relations` 或下一轮计划。

图谱生成仍只消费 `optimized_ontology.objects` 和 `optimized_ontology.relations`。校准包不能替图谱脚本补边。

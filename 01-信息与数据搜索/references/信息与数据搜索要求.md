# 信息与数据搜索要求

本文件定义投研本体生产流程中的来源搜索、材料登记和质量评估规则。本 Skill 的目标是形成可追溯材料底座，不做本体诊断、历史回放、优化或评测。

## 1. 输入识别

| 输入 | 处理 |
|---|---|
| `research_topic.md` | 必填。提取研究主题、范围、关键对象、产业链环节、时间窗口和下游目的。 |
| `downstream_task_list.md` | 可选。用于确定优先材料类型和搜索深度。 |
| `user_source_preferences.md` | 可选。记录用户指定来源、排除来源和检索偏好。 |
| `raw_materials/` | 可选。先登记用户材料，再判断是否需要补搜。 |

研究主题不清时，先输出澄清问题和最小搜索方案，不得伪造来源。

## 2. 来源类型

按用途组织材料，不按文件格式组织材料。

| 类型 | 例子 | 默认可靠性 |
|---|---|---|
| `policies` | 政策原文、监管文件、政府公告 | high |
| `announcements` | 公司公告、交易所文件、招股书、问询回复 | high |
| `financial_reports` | 年报、季报、业绩说明会材料 | high |
| `industry_data` | 官方统计、行业协会、可追溯数据库、价格数据 | high/medium |
| `reports` | 券商研报、咨询报告、行业白皮书 | medium |
| `news` | 新闻原文、媒体采访、转载报道 | medium/low |
| `data_extracts` | 表格、网页摘录、API 回灌结果 | 取决于原始来源 |
| `restricted` | 目标价、评级、推荐语、收益率预测、仓位表达 | restricted |

二手摘要、AI 摘要、无原文位置材料只能登记为线索，不得作为关键事实来源。

## 3. 搜索策略

1. 先找权威来源：政策原文、公告、财报、交易所文件、官方数据。
2. 对概念定义、产业范围、术语边界和同义词，优先找国家标准、统计分类、政策原文、行业协会、交易所文件、招股书、年报等权威来源。
3. 再找研究解释来源：研报、行业报告、专家访谈、调研纪要。
4. 最后找新闻和二手材料，用于发现事件或关键词，不用于确认关键事实。
5. 对每个核心变量至少尝试覆盖事实来源、解释来源和跟踪数据三类材料。
6. 对最新事件、价格、政策、公司动态必须记录查询时间和发布时间。

当资料冲突时，不合并成单一结论；在登记表中保留冲突来源、冲突点和建议核验方式。

## 4. `source_registry.json`

每份材料登记为一个对象。字段必须简洁但可追溯。

| 字段 | 要求 |
|---|---|
| `source_id` | 稳定唯一 ID，建议 `SRC-001`。 |
| `title` | 原标题或可识别标题。 |
| `publisher` | 发布主体。未知时写 `unknown`。 |
| `publish_date` | 发布时间。未知时写空并说明。 |
| `business_time` | 材料涉及的业务时间或数据区间。 |
| `source_type` | 使用第 2 节类型。 |
| `source_path_or_url` | 本地路径或 URL。 |
| `original_location` | PDF 页码、章节、表号、网页锚点或截图说明。 |
| `reliability` | `high`、`medium`、`low`、`restricted`。 |
| `topic_tags` | 主题、对象、变量、产业链环节标签。 |
| `concept_tags` | 可支持的概念、术语、边界或同义词标签。 |
| `key_claims` | 材料可支持的事实或线索，避免大段摘抄。 |
| `limitations` | 口径、时效、转载、样本偏差、冲突或访问限制。 |
| `usable_for` | 可用于缺口发现、历史案例、优化、评测或来源摘要。 |
| `restricted_items` | 若含受限内容，列出类型和处理方式。 |
| `evidence_level_hint` | 对后续 evidence_level 的建议，不等于最终确认。 |
| `episode_seed` | 供 6-8 Evidence Episode 归一使用的摄入线索，包含 episode_type、source_path_or_url、publish_time、business_time、original_location、ingest_hint、reliability、topic_tags、key_claims、limitations。 |
| `registered_at` | 登记时间。 |
| `notes` | 其他必要说明。 |

`episode_seed` 示例：

```yaml
episode_seed:
  episode_type: source_material
  source_path_or_url: ""
  publish_time: ""
  business_time: ""
  original_location: ""
  ingest_hint: "可作为 EvidenceEpisode 输入，待 6-8 归一 claim"
  reliability: high
  topic_tags: []
  key_claims: []
  limitations: []
```

6-1 只登记 `episode_seed`，不确认 EvidenceClaim 或 EvidenceFact。

## 5. 材料质量评估

输出 `source_quality_assessment.md`，使用七章结构：

1. 搜索范围和研究主题。
2. 材料总览：数量、类型、时间分布、可靠性分布。
3. 权威来源覆盖：政策、公告、财报、官方数据是否足够。
4. 核心变量覆盖：每个关键对象/变量有哪些来源，缺什么。
5. 冲突和限制：口径冲突、时间冲突、来源弱点、样本偏差。
6. 受限内容处理：目标价、评级、收益率预测、仓位表达等如何隔离。
7. 下游交接：哪些材料可用于缺口发现、历史案例、优化和评测。

质量判断只评价材料，不判断本体覆盖，不输出发布结论。

## 6. 搜索日志

输出 `source_search_log.md`，记录：

- 检索时间。
- 检索关键词。
- 检索渠道。
- 命中材料。
- 未命中材料。
- 放弃原因。
- 需要用户补充或授权的材料。

日志应能解释为什么某些关键材料不存在、不可访问或暂未纳入。

## 7. 输出目录

```
source_materials/
  policies/
  announcements/
  financial_reports/
  industry_data/
  reports/
  news/
  data_extracts/
  restricted/
source_registry.json
source_search_log.md
source_quality_assessment.md
```

材料文件名建议包含 `source_id`、日期和简短标题。不要把同一材料复制到多个目录；需要多用途时用 `usable_for` 标记。

## 8. 质量门槛

| 检查项 | 阻断条件 |
|---|---|
| 可追溯 | 关键材料没有路径、URL、页码、章节或原文位置。 |
| 来源分级 | 可靠性全为 low，却被标记为可支撑关键事实。 |
| 时间有效 | 最新事件、价格或政策缺少发布时间或查询时间。 |
| 受限隔离 | 目标价、评级、推荐语、收益率预测或仓位表达进入事实材料。 |
| 下游可用 | `source_registry.json` 缺少 key_claims、limitations 或 usable_for。 |
| Episode 交接 | 关键材料缺少 episode_seed，导致 6-8 无法稳定摄入。 |

出现阻断条件时，输出材料包但标记为不满足质量门槛，并说明补救动作。

## 9. 禁止事项

- 不判断本体覆盖等级。
- 不输出缺口清单、历史回放结论、优化本体、评测结论或发布结论。
- 不伪造来源，不把 AI 生成内容冒充搜索结果。
- 不用无法追溯材料支撑关键事实。
- 不把预测、评级、目标价、推荐语、收益率推断或仓位表达登记为事实观测。
- 不直接抽取或确认 EvidenceFact；正式 episode、claim 和 fact 由 6-8 归一校验。
